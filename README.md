# 내 투자 노트 (2단계: 재무·안전 점검 추가)

내 자산 + 종목 리포트(실제 시세) + 규칙 화면이 있는 앱이에요.
보유 종목은 내 구글 시트에 저장돼요. 구글 시트 연결 전에는 **데모 모드**로 열려요(저장 안 됨).

## 전체 순서 (약 30~40분, 한 번만 하면 돼요)

- A. 구글 시트 + 저장 코드 붙이기 (10분)
- B. GitHub에 파일 올리기 (10분)
- C. Streamlit Cloud에 올리고 비밀 설정 넣기 (10분)
- D. 폰 홈 화면에 추가

돈이 오가는 계정(증권사 ID/비밀번호, API 키)은 이 앱에 전혀 필요 없어요.

---

## A. 구글 시트 + 저장 코드

1. 구글 시트를 새로 만들어요. 이름은 `투자노트 데이터` 같은 아무 이름이나 괜찮아요.
2. 메뉴 `확장 프로그램 > Apps Script`를 열어요.
3. 기존 코드를 모두 지우고 `Code.gs` 파일 내용을 통째로 붙여넣고 저장해요.
4. 왼쪽 톱니바퀴 `프로젝트 설정`을 누르고, 아래쪽 `스크립트 속성`에서 `스크립트 속성 추가`를 눌러요.
   - 속성: `TOKEN`
   - 값: 아무도 모를 긴 문자열(영문+숫자 30자 이상). 메모장에 따로 적어두세요. 아래 C단계에서 또 써요.
5. 오른쪽 위 `배포 > 새 배포`를 눌러요.
   - 유형 선택(톱니바퀴): `웹 앱`
   - 다음 사용자 인증 정보로 실행: `나`
   - 액세스 권한이 있는 사용자: `모든 사용자`
   - `배포`를 누르고, 처음 한 번 `액세스 승인`을 해줘요(안전하지 않다는 안내가 나오면 `고급 > 이동`).
6. 나오는 `웹 앱 URL`(https://script.google.com/macros/s/…/exec)을 복사해서 메모장에 적어두세요.

> 이 주소는 TOKEN 없이는 아무것도 읽거나 쓰지 못해요. 그래도 주소와 TOKEN은 남에게 알려주지 마세요.
> 나중에 Code.gs를 고치면 `배포 > 배포 관리 > 연필 > 새 버전`으로 다시 배포해야 반영돼요.

## B. GitHub에 파일 올리기

1. github.com에서 무료 계정을 만들어요.
2. 오른쪽 위 `+ > New repository`를 눌러요.
   - 이름: `stock-note`
   - **Private(비공개)** 선택, `Create repository`
3. 만들어진 화면에서 `uploading an existing file` 링크를 눌러요.
4. 아래 5개 파일을 끌어다 놓고 `Commit changes`를 눌러요.
   - `app.py`, `market.py`, `signals.py`, `store.py`, `requirements.txt`
   - `Code.gs`와 `README.md`는 올리지 않아도 돼요.

## C. Streamlit Cloud에 올리기

1. share.streamlit.io에 접속해서 GitHub 계정으로 로그인해요.
2. `Create app`(또는 `New app`) > GitHub 저장소 `stock-note`, 브랜치 `main`, 파일 `app.py` 선택해요.
3. 배포하기 전에 `Advanced settings > Secrets` 칸에 아래 내용을 붙여넣고 값을 바꿔요.

```
APP_PASSWORD = "내가 정한 앱 비밀번호"
GAS_URL = "A단계 6번에서 복사한 웹 앱 URL"
GAS_TOKEN = "A단계 4번에서 정한 TOKEN"
```

4. `Deploy`를 눌러요. 처음에는 몇 분 걸려요.
5. 앱 설정에서 공개 범위를 확인하세요. 저장소를 Private으로 만들었으면 비공개 앱으로 쓸 수 있고(무료 계정은 비공개 앱 1개), 이 앱은 비밀번호 화면도 따로 있어요.

## D. 폰에서 쓰기

폰 브라우저로 앱 주소를 열고, 메뉴에서 `홈 화면에 추가`를 누르면 앱처럼 쓸 수 있어요.

---

## 처음 쓰는 순서

1. 앱을 열고 비밀번호를 입력해요.
2. `내 자산` 아래쪽 `보유 종목 편집`에서 보유 종목을 입력하고 `저장`을 눌러요.
   - 증권사 / 종목코드(6자리) / 종목명 / 꼬리표(중장기·스윙) / 수량 / 평균단가
3. 카카오 소수점 정기매수는 종목명 / 티커(NVDA) / 하루금액 / 시작일을 입력해요.
4. 구글 시트를 열어보면 `보유종목`, `정기매수` 탭이 생겨 있어요. 시트에서 직접 고쳐도 돼요.

## 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| "시세를 가져오지 못했어요" | 종목코드 6자리 확인. 잠시 뒤 `시세 새로고침`. 무료 시세 출처가 일시적으로 막히는 경우가 있어요 |
| "구글 시트에서 불러오지 못해서 저장을 막았어요" | GAS_URL·GAS_TOKEN 확인. Apps Script 배포가 `모든 사용자` 접근인지 확인 |
| 비밀번호 설정 안내가 뜸 | Secrets에 APP_PASSWORD를 넣었는지 확인 |
| 데모 모드라고 나옴 | Secrets에 GAS_URL과 GAS_TOKEN이 둘 다 있는지 확인 |

## 이 단계에서 되는 것 / 아직 안 되는 것

- 되는 것: 증권사별 합산, 종목별 수익률, 쏠림 경고, 가격 기준 신호(손절선·목표·20일선·RSI·눌림목), 종목 차트, 카카오 정기매수 추정 계산
- 아직 없는 것: 재무·안전 기준(DART), 수급, 증권사 리포트, 종목 발굴, 매매일지, 규칙 저장, 알림

## 2단계 업데이트 방법 (DART 재무·안전 점검)

### 1) GitHub에 파일 6개 올리기 (같은 이름은 덮어써져요)

`Add file > Upload files`로 아래를 한꺼번에 올리고 `Commit changes`를 눌러요.

- `app.py` (교체)
- `market.py` (교체)
- `requirements.txt` (교체)
- `dart_data.py` (새 파일)
- `safety.py` (새 파일)

### 2) Streamlit Secrets에 DART 인증키 줄 추가

`My apps > stock-note > ⋮ > Settings > Secrets`에서 기존 3줄은 그대로 두고, 아래 한 줄을 **추가**한 뒤 `Save`를 눌러요.

```
DART_API_KEY = "발급받은 40자리 인증키"
```

따옴표 안에 실제 키를 넣어야 해요(예시 문구 그대로 두면 안 돼요). 키는 채팅에 보내지 마세요.

### 3) 쓰는 순서

1. 앱을 열면 탭이 4개가 돼요: 내 자산 / **안전 점검** / 종목 리포트 / 규칙
2. **안전 점검** 탭에서 `재무·공시 가져오기`를 눌러요. 보유 종목 수에 따라 1~3분 걸려요.
3. 끝나면 종목별 결과가 표로 나와요. 한 번 가져온 데이터는 구글 시트의 `재무캐시` 탭에 저장돼서 7일 동안 다시 가져오지 않아요.
4. **종목 리포트** 탭에서 종목을 고르면 재무 지표, 영업이익 3개년, 안전 기준별 통과·미달, 그리고 근거 데이터가 나와요.
5. **규칙** 탭 아래쪽에서 안전 기준 숫자를 바꾸거나 항목을 끌 수 있어요.

### 안전 점검 항목

시가총액, 최근 3년 영업적자, 이자보상배율, 부채비율, 영업활동현금흐름, 자본잠식, 감사의견, 부도·회생·관리절차 공시, 최근 3년 현금배당, 최대주주 지분율, 최근 3년 증자·전환사채 등 발행 결정, 일평균 거래대금

- 확인하지 못한 항목은 미달로 치지 않고 **확인 불가**로 따로 표시해요.
- 금융업(은행·보험·증권)은 부채비율, 이자보상배율, 영업현금흐름이 의미가 달라서 해당 없음으로 처리해요.
- **투자경고·관리종목 지정**은 DART에서 가져올 수 없어서 점검에 포함되지 않아요.

### 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| "DART_API_KEY가 설정되어 있지 않아요" | Secrets에 DART_API_KEY 줄이 있는지, 따옴표 안에 실제 키가 들어 있는지 |
| "DART 응답 010 / 011" | 인증키가 잘못됐거나 사용 정지된 키예요. DART 사이트에서 키 상태 확인 |
| "DART 응답 020" | 하루 사용 한도를 넘었어요. 내일 다시 시도 |
| 항목이 많이 확인 불가로 나옴 | `종목 리포트`의 근거 데이터에서 errors 칸을 확인하고 알려주세요 |
| 앱이 오류 화면(Traceback) | 화면을 캡처해서 보여주세요 |

## 3단계 업데이트 방법 (종목 발굴)

### 1) GitHub에 파일 4개 올리기 (같은 이름은 덮어써져요)

- `app.py` (교체)
- `dart_data.py` (교체)
- `safety.py` (교체)
- `discover.py` (새 파일)

`requirements.txt`는 그대로예요. Secrets도 그대로 쓰고, 새로 추가할 것은 없어요.

### 2) 쓰는 순서

1. 앱에 **종목 발굴** 탭이 생겨요(탭 순서: 내 자산 / 종목 발굴 / 안전 점검 / 종목 리포트 / 규칙).
2. `발굴 조건`을 열어 기준을 확인하고(처음엔 기본값 그대로 괜찮아요), **`시장 데이터 불러오기`**를 눌러요. 처음에는 1~3분 걸려요.
3. 깔때기 숫자가 나와요: 전체 종목 → ① 목록 필터 통과 → ② 재무 조회됨 → ② 재무 조건 통과
4. 표에서 후보를 보고, 아래 **`상위 후보 상세 점검`**을 눌러요. 상위 N개를 DART 안전 기준과 가격 흐름까지 점검해요.
5. 마음에 드는 종목은 **`관심종목에 추가`**를 눌러요. 구글 시트의 `관심종목` 탭에 저장되고, 종목 리포트 탭의 종목 선택에 나와요.
6. 조건을 바꾼 뒤 **`조건 저장`**을 누르면 구글 시트에 남아요.

### 알아두세요

- **PER·PBR은 추정치**예요. 오늘 시가총액을 최근 사업보고서의 순이익·자본총계로 나눠요.
- 종목 목록 출처에 접속하지 못하면 종목코드를 직접 붙여넣는 방식으로 바뀌어요(시가총액 조건은 빠져요).
- **관리종목**은 거래소 목록(KIND)으로 안전 점검에 추가됐어요. 목록을 못 불러오면 확인 불가로 표시돼요. 투자경고·투자주의 지정은 아직 점검하지 못해요.
- 우선주, 스팩은 후보에서 자동으로 제외돼요. 금융업으로 보이는 종목(이름에 금융·은행·증권·보험 등)은 부채비율 조건을 면제해요.

### 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| "종목 목록을 가져오지 못했어요" | 잠시 뒤 다시 시도. 계속되면 나오는 안내대로 종목코드를 직접 붙여넣기 |
| "DART 재무 조회에 실패했어요" | 오류 문구의 숫자(010·011은 키 문제, 020은 하루 한도 초과) 확인 |
| 재무 조회됨 숫자가 ①보다 훨씬 적음 | 최근 사업보고서가 아직 없는 종목이에요. 정상일 수 있어요 |
| 조건을 통과한 종목이 0개 | 발굴 조건에서 ROE·PER를 완화 |

## 4단계 업데이트 방법 (목표·성과)

### 1) GitHub에 파일 2개 올리기

- `app.py` (교체)
- `perf.py` (새 파일)

Secrets와 `requirements.txt`는 그대로예요.

### 2) 처음 한 번 해둘 것

1. 앱의 **목표·성과** 탭을 열면 오늘 자산이 자동으로 기록돼요(구글 시트에 `자산기록` 탭이 생겨요).
2. 탭 아래 **자산 기록 관리**를 열어요.
3. **현금**: 증권사 계좌들의 예수금을 합쳐서 `지금 현금`에 넣고 `지금 기록하기`를 눌러요. 총자산 = 주식 평가금액 + 현금이에요.
4. **연초 기준**: 표 맨 아래 빈 줄에 `날짜`(작년 12월 말, 예: 2025-12-31)와 `총자산`(그날 증권사 앱 평가금액 합계)만 적고 `자산 기록 저장`을 눌러요.
5. **입출금**: 올해 증권 계좌 밖에서 들어온 돈은 +, 빠져나간 돈은 -로 적고 `입출금 저장`을 눌러요(주식 사고팔기는 입출금이 아니에요).
6. **올해 목표 설정**을 열어 기대 범위와 허용 낙폭을 정하고 `목표 저장`을 눌러요.

### 매달 할 일

월말에 앱을 한 번 열어서 현금을 갱신하고 `지금 기록하기`를 눌러요. 앱을 열지 않은 날은 기록이 없어요.

### 보는 법

- **올해 수익률(입금 보정)**: 새로 넣은 돈을 뺀 수익률이에요. 입금을 기록하지 않으면 입금이 수익처럼 보여요.
- **고점 대비 낙폭**: 내 자산이 최고점에서 얼마나 내려왔는지예요. 허용 낙폭을 넘으면 경고가 떠요.
- **월말 자산**: 그 달 마지막 기록과 월간 수익률이에요.

## 5단계 업데이트 방법 (수급 흐름)

### 1) GitHub에 파일 올리기

- `app.py` (교체)
- `signals.py` (교체)
- `flows.py` (새 파일)

Secrets와 `requirements.txt`는 그대로예요(표를 읽는 부품은 이미 들어 있어요).

### 2) 어디서 보나요

- **종목 리포트 탭**: 종목을 고르면 아래쪽에 **수급 흐름**이 자동으로 나와요. 외국인·기관·개인(추정)의 5일·20일 순매수 금액, 일별 막대, 외국인 보유율, 한 줄 해석이 있어요.
- **내 자산 탭**: `보유 종목 수급 가져오기`를 누르면 보유 종목 표에 `수급(5일)` 칸이 채워져요. 스윙 종목이 외국인·기관 동반 순매도면 신호에 같이 표시돼요.
- **종목 발굴 탭**: `상위 후보 상세 점검`을 누르면 외국인·기관 5일 순매수 칸도 같이 나와요.

## 종합 판단 카드와 판단 기록

이 앱의 목적은 현황을 보는 것이 아니라 **판단의 근거를 데이터로 모으고, 내 판단이 실제로 맞았는지 검증하는 것**이에요.

### 올릴 파일

- `app.py`, `market.py` (교체)

### 종합 판단 카드 (종목 리포트 탭)

종목을 고르면 신호 아래에 카드가 나와요.

- **보수적 상승 여력**: 컨센서스 목표가의 절반, 가까운 저항선 중 작은 값
- **하락 위험**: 가까운 지지선(단기), 그 아래 지지선·과거 큰 되돌림(중기), 52주 저점(극단)
- **손익비**와 등급(유리·보통·다소 불리·불리), **필요 승률**(이 손익비에서 본전이 되려면 이 정도 이상 맞혀야 해요)
- **내 평단 기준 시나리오 표**: 각 가격에서 내 수익률, 손익 금액, 총자산에 주는 영향
- **계획 이탈 경고**: 스윙 종목이 손절선을 넘어 들고 있을 때 등
- **근거 충족도**: 가격 흐름, 컨센서스, 수급, 안전·재무 중 몇 개를 반영했는지

### 판단 기록 탭

- 카드 아래 **`이 카드로 판단 기록하기`**, 또는 판단 기록 탭의 **월간 점검**(30일 넘게 기록이 없는 보유 종목을 한 번에 기록)을 써요.
- 기록하는 순간의 카드 숫자와 결정(매수·추가 매수·보유 유지·일부 매도·전량 매도·관망), 이유, 확신도, 무효가격(손실 한도), 메모가 구글 시트의 `판단기록` 탭에 저장돼요.
- **20·60·120거래일 뒤의 결과**가 자동으로 붙어요: 수익률, 결정 손익(사거나 들고 있는 결정은 오르면 +, 팔거나 사지 않은 결정은 내리면 +), 코스피 대비, 기간 중 최대 하락, 무효가격 이탈 여부
- 통계: 결정 유형별·확신도별·카드 등급별·이유별 건수, 맞은 비율, 평균 이익·손실, 손익비, **건당 기대값**. 건수가 20건 미만이면 '참고만'으로 표시돼요.

### 매달 할 일

월말에 판단 기록 탭의 월간 점검을 열어서 보유 종목마다 결정을 남기세요(보유 유지도 결정이에요). 내 자산 탭 맨 위에 점검이 필요한 종목 수가 안내돼요.

## 속도 개선

기능이 늘면서 느려진 걸 구조로 고쳤어요.

- **탭 대신 화면 선택**: 이전에는 화면을 바꾸거나 버튼을 누를 때마다 7개 탭을 전부 다시 계산했어요. 이제 맨 위의 화면 이름을 눌러 이동하고, **고른 화면만** 계산해요.
- **시세를 동시에 가져와요**: 보유 종목 시세를 한 종목씩이 아니라 한꺼번에 가져와서 앱을 처음 열 때가 빨라졌어요(12종목 기준 약 6초 → 약 1.5초, 종목당 0.5초로 가정한 시험).
- **계산 결과를 저장해요**: 입력이 같으면 보유 종목 표를 다시 계산하지 않아서 같은 화면을 다시 그릴 때 0.3초 정도예요.
- 하루 한 번 자동 기록은 어느 화면을 열든 앱을 열 때 한 번 실행돼요.
- 시세는 15분 동안 저장해요. 바로 새로 받으려면 왼쪽 사이드바의 `시세 새로고침`을 누르세요.

## 가설 실험실 (지표를 검증해서 쓰기)

모든 지표는 가설이에요. 20일선, 60일선, 볼린저 밴드, 이격도, RSI, 52주 고점, 거래량 같은 흔한 지표가 **한국 종목에서 실제로 효과가 있었는지** 과거 가격으로 재봐요.

### 올릴 파일

`lab.py`(새 파일), `app.py`, `guide.py`

### 쓰는 법 (새 화면 "가설 실험실")

1. 종목 수(시가총액 상위), 기간(3·5년), 보유 기간(20·60거래일), 왕복 비용을 정하고 `가설 검증 실행`을 눌러요. 처음에는 과거 가격을 가져오느라 몇 분 걸릴 수 있어요.
2. 가설별로 **표본 수, 승률과 기준선 승률, 시장 평균을 뺀 평균 초과수익과 신뢰구간, 앞·뒤 기간의 일관성, 등급**이 나와요.
3. 두세 개를 **조합**해서 교차 검증할 수 있어요.
4. 결과는 구글 시트의 `가설결과` 탭에 쌓이고, 종목 리포트의 신호 풀이에 "우리 검증" 결과로 같이 표시돼요.

### 결과를 읽는 법

- **검증됨(약함)**: 평균 초과수익의 신뢰구간이 0보다 크고, 앞·뒤 절반 기간이 같은 방향
- **가설(방향만)**: 방향은 플러스지만 우연과 구분되지 않음
- **효과 구분 안 됨**: 차이를 가려내지 못함(효과가 없다는 뜻이 아니라 이 표본으로는 구분이 안 된다는 뜻)
- **불리함 확인(피하는 근거)**: 신뢰구간이 0보다 작고 일관됨
- **표본 부족**: 이벤트가 200건 미만

### 통계 원칙

- 승률 50%와 51%를 구분하려면 약 1만 건이 필요해서, 여러 종목과 여러 해의 이벤트를 모아요.
- 시장 평균을 뺀 초과수익으로 비교하고, 같은 종목의 겹치는 날은 한 번만 세요.
- 시험한 가설 수만큼 신뢰 수준을 엄격하게 올려요(다중검정 보정). 효과를 심지 않은 가짜 데이터에서 96번 시험해서 '검증됨' 오판이 0번인 것을 확인했어요.
- **한계**: 지금 상장된 종목만 쓰기 때문에 상장폐지 종목이 빠져 있어(생존 편향) 결과가 실제보다 좋게 나올 수 있어요. 과거 효과가 미래를 보장하지 않아요.

### 수급 기록 쌓기

화면 아래 `보유·관심 종목의 수급 기록하기`를 한 달에 한 번 이상 누르면 구글 시트 `수급기록` 탭에 일별 외국인·기관·개인 수급이 쌓여요. 6개월 이상 쌓이면 "외국인·기관 수급이 중장기 성과를 높이는가" 같은 수급 가설을 같은 방식으로 검증할 수 있어요.

## 목적 자금: 현재 금액은 주식 잔고로 자동

이 앱은 **주식 투자금액만** 관리해요. 목적 자금 화면의 현재 금액을 직접 적지 않고, **주식 잔고(보유 종목 평가금액 + 카카오 정기매수 평가금액)를 합산해서 자동으로** 써요.

- 화면 위쪽에 **현재 주식 투자금액**(보유 종목, 정기매수 따로)이 보이고, 시세에 따라 매일 바뀌어요.
- 목적(자녀 분가, 노후 등)마다 **배분(%)**을 정하면 `현재 배분 금액 = 주식 투자금액 × 배분 비율`이 자동으로 들어가요. 합계가 100%를 넘으면 100%에 맞춰 줄여서 계산하고, 100% 미만이면 나머지는 "어느 목적에도 속하지 않은 투자금액"으로 보여줘요.
- **매달 투입**은 매달 주식에 새로 넣는 돈이에요(옛 '매달 저축' 값은 자동으로 옮겨져요).
- 기본은 주식 평가금액만 쓰고, 체크하면 목표·성과에서 마지막으로 기록한 **계좌 현금**도 포함해요.
- 예금·부동산·연금 같은 다른 자산은 반영하지 않아요.

`app.py`, `guide.py`

### 바뀐 점 (가설 실험실 아래쪽)

- **기간 시험(1종목)**: 네이버가 한 종목에 대해 500거래일을 실제로 주는지 확인해요.
- **수급 기록하기**: 한 번에 가져올 기간(40·120·250·500거래일)을 고르고, **검증용으로 시가총액 상위 종목도 함께** 기록할 수 있어요. 5등분 비교는 종목이 수십 개 이상 있어야 해서 필요해요.
- **수급 가설 검증 실행**: 쌓인 수급 기록으로 큰손(외국인+기관), 외국인, 기관, 개인(개인 주도 가설)의 20일 순매수 비중을 5등분해서 이후 수익을 비교해요. 종목 30개 이상이 150거래일 이상 있어야 믿을 만하고, 부족하면 화면에 알려줘요.
- 종합 점수의 수급 항목(큰손 순매수 비중, 개인 주도 경고)에 이 검증 결과가 같이 표시돼요.

### 알아두세요

- 네이버가 요청한 만큼 긴 기간을 주지 않을 수 있어요. 그러면 기록이 쌓이는 만큼만 검증돼요(앞으로 한 달에 한 번 이상 기록).
- 시가총액 상위 종목을 많이 기록할수록 오래 걸리고 시트가 커져요(100종목 × 250거래일 ≈ 2.5만 줄).
- 큰손·외국인·기관 결과는 같은 데이터를 다르게 자른 것이라 독립된 확인이 아니에요.

## 검증 결과를 점수에 반영

가설 실험실에서 나온 검증 결과가 **종합 점수의 근거 비중과 방향**에 자동으로 반영돼요. 종목 선정(종합 순위, 매수 후보)과 보유 종목 점검(주간 브리핑, 내 자산 표)에 같은 기준이 적용돼요.

### 올릴 파일

`score.py`(2번 버전), `app.py`, `guide.py`

### 반영 규칙

| 가설 실험실의 결과 | 반영 배율 | 방향 |
|---|---|---|
| 검증됨(약함), 불리함 확인 | 1.0 | 결과 방향을 따라요(반대로 검증되면 점수를 뒤집어요) |
| 가설(방향만) | 0.7 | 결과의 부호 방향 |
| 효과 구분 안 됨 | 0.3 | 그대로 |
| 표본 부족 / 시험 안 함 | 0.5 | 그대로 |

- 같은 항목에 가설이 여러 개면(예: 추세 = 60일선 위, 20일선 위, 정배열) **가장 좋은 것을 고르지 않고 평균**을 써요. 우연히 좋게 나온 하나에 기대지 않기 위해서예요.
- 시험하지 않은 근거를 100%로 두면 검증을 안 하는 게 유리해지므로 50%로 둬요.
- 근거 종류(가격 흐름, 수급 등)의 비중은 `규칙 탭의 가중치 × 그 종류 항목들의 평균 배율`로 정해져요.
- **'근거 검증 수준'**: 종합 점수가 검증된 근거에 얼마나 기대는지(100% 가까이면 검증된 근거 중심, 50% 안팎이면 미검증·효과 불분명 중심)
- 점수 카드의 항목 표에 **원점수, 반영 점수, 반영 배율, 검증 결과**가 나와요.
- 규칙 탭의 `검증 결과로 근거 비중·방향을 자동 조정`을 끄면 모든 근거를 그대로 평가해요.

## DART가 안 될 때 네이버 금융 재무로 대신하기

DART 연결이 안 돼도 **종목 발굴, 안전 점검, 종목 리포트가 멈추지 않도록** 네이버 금융의 재무로 자동 대체해요.

### 올릴 파일

`naverfin.py`(새 파일), `app.py`, `discover.py`, `safety.py`, `guide.py`

### 대체 자료로 확인되는 것과 안 되는 것

| 확인됨 (네이버 금융) | 확인 안 됨 (DART 공시에만 있음) |
|---|---|
| 최근 3년 영업이익과 영업적자 횟수, 매출액, 당기순이익 | 이자보상배율, 영업활동현금흐름 |
| 부채비율, ROE, PER, PBR | 자본잠식, 감사의견 |
| 최근 3년 주당배당금(배당 이력) | 최대주주 지분율, 증자·CB·BW 이력, 부도·회생 공시 |

확인 안 되는 안전 기준은 '확인 불가'로 표시되고 미달로 치지 않아요(그래서 대체 중에는 안전 점검이 실제보다 관대하게 보여요).

### 어떻게 동작하나

- **종목 발굴**: `재무 자료 출처`를 `자동(DART 우선)`, `네이버 금융`, `DART` 중에서 골라요. 자동이면 DART가 안 될 때 네이버 금융으로 넘어가고(종목당 1회 요청이라 300종목이면 1~2분), 결과 화면에 출처가 표시돼요.
- **상세 점검, 안전 점검, 종목 리포트**: 종목마다 DART를 먼저 시도하고, 안 되면 네이버 금융으로 대신해요. 대체 자료는 하루만 쓰고 다음 날 다시 DART를 시도해요.
- 이전에는 DART가 안 되면 종목 발굴과 안전 점검 화면이 **통째로 멈췄는데**, 이제는 안내만 띄우고 계속 진행돼요.

### 알아두세요

네이버 금융의 데이터 형식을 이 환경에서 직접 확인하지는 못해서, 형식이 다르면 실패 이유가 화면에 나와요.

## DART 수집기 (내 PC에서 실행)

DART가 **해외 서버(Streamlit Cloud)의 접속을 막을 때**를 위한 방법이에요. 한국 IP인 **내 PC**에서 DART를 조회해 구글 시트에 저장해 두면, 앱은 DART에 직접 접속하지 않고 시트의 자료를 읽어요. 자료는 일주일에 한 번, 또는 DART가 막혔을 때만 갱신하면 돼요.

### 먼저 원인을 가려내는 시험 (1분)

1. 내 PC 브라우저에서 `https://opendart.fss.or.kr` 이 열리는지 봐요. **열리면** DART 서버는 정상이고, 앱이 있는 해외 서버만 막힌 가능성이 커요(이 방법이 맞아요). **안 열리면** DART 서버 장애이니 기다리세요.
2. (선택) 구글 시트 Apps Script 편집기에서 아래 함수를 실행해 보면, 구글 서버에서 DART가 되는지 알 수 있어요. 되면 앱이 Apps Script를 통해 DART를 부르게 만들 수 있어요(키는 본인 것으로 바꿔 넣고, 이 글을 다른 곳에 붙여넣지 마세요).
```
function testDart() {
  var r = UrlFetchApp.fetch('https://opendart.fss.or.kr/api/company.json?crtfc_key=여기에키&corp_code=00126380', {muteHttpExceptions: true});
  Logger.log(r.getResponseCode() + ' ' + r.getContentText().slice(0, 100));
}
```

### 준비 (처음 한 번)

1. 이 폴더(앱 파일 전체)를 내 PC에 내려받아요(GitHub 저장소의 `Code` > `Download ZIP`).
2. 파이썬이 없으면 설치하고, 명령 프롬프트에서 아래를 한 번 실행해요.
   `pip install requests pandas finance-datareader lxml beautifulsoup4 html5lib`
3. `collector_config.example.json`을 복사해서 이름을 **`collector_config.json`**으로 바꾸고 값 세 개를 채워요(Streamlit Secrets에 넣은 것과 같은 값: `GAS_URL`, `GAS_TOKEN`, `DART_API_KEY`).
   **이 파일은 비밀번호가 들어 있으니 GitHub에 올리지 마세요**(`.gitignore`에 이미 제외돼 있어요).

### 실행

폴더에서 명령 프롬프트를 열고 `python local_collector.py`를 실행해요.

- **보유·관심 종목의 상세 재무·공시**를 시트 `재무캐시`에 저장해요(안전 점검, 종목 리포트가 읽어요). 7일 안에 가져온 종목은 건너뛰어요.
- **시가총액 상위 600종목의 연간 재무**를 시트 `발굴재무`에 저장해요(종목 발굴 2단계가 읽어요). `--top 300`처럼 개수를 바꿀 수 있어요.
- 옵션: `--only holdings` / `--only discover`, `--codes 005930,000660`(추가 종목), `--force`(최근 것도 다시)
- 끝나면 앱을 새로고침하세요.

### 앱에서 쓰이는 순서

종목 발굴의 `재무 자료 출처`가 `자동`이면 **DART → 내 PC 수집본 → 네이버 금융** 순서로 써요. 수집본이 일부 종목만 있으면 나머지만 네이버 금융으로 채워요. 결과 화면에 어느 출처인지 표시돼요. 안전 점검과 종목 리포트는 시트 `재무캐시`가 최신이면(7일 이내) 그걸 그대로 써요.

## 종목 발굴이 멈추던 문제 수정 (실제 화면에서 확인한 두 가지)

크롬으로 실제 앱을 열어서 종목 발굴을 돌려보고 찾은 문제예요.

1. **DART가 안 되는데도 4분 가까이 기다렸어요.** 회사 목록을 시트 보관본으로 열어서 "연결됨"으로 착각하고, 재무를 묶음마다 25초씩 기다렸다가 실패한 뒤에야 네이버로 넘어갔어요. 이제 DART가 **실제로 응답하는지 먼저 짧게(최대 6초) 확인**하고, 안 되면 바로 네이버 금융으로 넘어가요. 일괄 조회 중에도 연결 오류가 나면 즉시 멈춰요.
2. **넘어간 뒤에도 후보가 0개였어요.** 종목 목록에 시가총액·거래대금이 비어 있어서(KRX 쪽도 막힌 것으로 보여요) 조건을 적용하지 못했고, PER도 시가총액이 있어야 계산돼서 비어 있었어요. 이제 **네이버 금융 시가총액 순위(코스피·코스닥 상위 600종목)로 시가총액과 거래대금을 채우고**, PER은 네이버가 주는 값을 보충해서 써요.

### 올릴 파일

`app.py`, `discover.py`, `dart_data.py`, `naverfin.py`(2번 버전), `guide.py`

### 알아두세요

- 시가총액 순위에 없는 작은 종목은 후보에서 빠져요(어차피 시가총액 1조원 이상 조건이에요).
- 네이버 금융으로 재무를 가져오는 건 실제 앱에서 **392종목이 성공**하는 걸 확인했어요.

## 종목 발굴 상세 점검 결과 저장

**문제**: 상세 점검의 재무 자료는 시트(`재무캐시`)에 저장됐지만, **상세 점검 결과 목록과 표는 화면(세션)에만 있어서** 새로고침하거나 앱이 다시 시작되면 사라졌어요.

**수정**: `상위 후보 상세 점검`을 누르면 결과가 구글 시트의 **`발굴결과` 탭에 자동으로 저장**돼요.
- 점검일, 종목, **점검가**, 안전 결과, 미달·확인 불가 항목, 진입 판정·손익비·무효가격·최대 매수·기다릴 가격, 수급, 흐름, 52주 위치, RSI, 3개월, 재무출처
- 같은 날 같은 종목을 다시 점검하면 새 값으로 바뀌어요(중복이 쌓이지 않아요).
- 종목 발굴 화면의 **"📌 저장된 상세 점검 결과"**에서 날짜별로 다시 볼 수 있어요(새로고침 후에도).
- **점검 후 변화(%)**: 점검한 날의 가격 대비 지금 가격의 변화예요. 발굴한 후보가 이후 어땠는지, 내 발굴 기준이 쓸 만했는지 확인하는 자료예요.

`app.py`, `helptext.py`, `guide.py`

## 코인 수량 소수점·매수금액 입력

### 올릴 파일

`coins.py`(2번 버전), `app.py`(`2026-10-13 수정14`), `helptext.py`

### 바뀐 것

- **수량을 소수점으로** 적을 수 있어요(예: `0.00123456`). 빈 표에서도 소수점을 받도록 수량·평균단가 칸을 숫자(실수) 칸으로 고정했고, 소수점 여덟 자리까지 유지돼요(시트를 오가도 그대로예요).
- 코인 편집 표에 **`매수금액`** 칸이 생겼어요. 세 가지(수량, 평균단가, 매수금액) 중 **두 가지만 알면 나머지는 저장할 때 계산해요.**
  - 수량을 모를 때: `평균단가` + `매수금액` → 수량 = 매수금액 ÷ 평균단가
  - 평균단가를 모를 때: `수량` + `매수금액` → 평균단가 = 매수금액 ÷ 수량
  - `매수금액` 칸은 저장하면 비워져요(시트에는 수량·평균단가만 저장돼요).
  - 셋 다 적었으면 수량과 평균단가를 그대로 써요.
- **수량을 알 수 없는 줄**(약어만 있고 수량도, 평균단가+매수금액도 없는 줄)은 저장 전에 **줄 번호를 알려주고 막아요.** 약어가 비어 있는 줄도 같아요.
- 코인 표에서 **가격이 작은 코인**(수십 원 이하, 소수점 단가)도 보이도록 평균단가·현재가를 형식에 맞춰 보여줘요. 수량은 소수점 여덟 자리까지 보여줘요.

### 예시

- 업비트에서 비트코인 평균매수가 1억 원, 매수금액 10만 원 → `평균단가 100000000`, `매수금액 100000` → 수량 `0.001`
- 도지코인 1,000.5개를 15만 원에 샀다 → `수량 1000.5`, `매수금액 150000` → 평균단가 약 149.93원

## 관심종목 관리 (보기·추가·이름 고치기·삭제)

### 올릴 파일

`app.py`(`2026-10-13 수정15`), `helptext.py`

### 어디에 있나

**종목 발굴 화면 위쪽**의 **`⭐ 관심종목 관리 (N개)`** 상자예요(`📋 현재 발굴 기준` 바로 아래). 종합 순위에는 "관심종목 N개가 `구분: 관심`으로 함께 나와요. 관리는 종목 발굴 위쪽에서"라는 안내가 붙어요.

### 할 수 있는 것

- **전체 목록 보기**: 종목명, 종목코드, **상태**(관심 / 보유 중), 현재가, 1개월 수익률, (`종합 점수도 계산`을 켜면) 종합 점수
- **종목코드로 직접 추가**: 6자리 코드(예: `033780`)와 이름(선택)
- **이름 고치기**: 종목명 칸을 고치고 `이름 변경 저장`
- **삭제**: `삭제` 칸에 체크하면 "N개를 관심종목에서 뺄까요? 종목A, 종목C"라고 확인을 물어요. **`삭제 확정`을 눌러야** 시트에서 지워져요(보유 종목에는 영향 없음)
- 구글 시트의 `관심종목` 탭과 **같은 목록**이에요. 시트에서 직접 고친 경우에는 앱을 새로고침한 뒤 쓰세요.

## 관심종목에 추가일·추가가 기록 ("담은 뒤 얼마나 올랐나")

### 올릴 파일

`app.py`(`2026-10-13 수정16`), `helptext.py`

### 바뀐 것

- 관심종목에 담을 때 **추가일**(담은 날)과 **추가가**(그날의 종가, 장 마감 전이면 직전 종가)를 같이 저장해요. 구글 시트 `관심종목` 탭에 `추가일`, `추가가` 열이 생겨요(예전 시트도 그대로 불러와지고, 새로 담을 때부터 4열로 저장돼요).
- **⭐ 관심종목 관리** 표에 `추가일`, `추가가(원)`, **`추가 후 변화(%)`**가 나와요. 담은 가격 대비 지금 가격의 변화예요.
- 담은 지 하루 이상 된 종목이 **3개 이상**이면 "추가 기록이 있는 N종목의 추가 후 평균 변화는 +x%, 오른 종목은 a/N개예요"를 보여줘요.
- 이름을 고치거나 삭제해도 다른 종목의 추가일·추가가는 그대로 유지돼요.

### 알아두세요

- **이 기능이 생기기 전에 담은 종목은 추가일·추가가가 비어 있어요.** 그때의 가격은 기록이 없어서 채울 수 없어요.
- 평균은 종목 수가 적으면 우연일 수 있고, 담은 시점이 제각각이라 기간이 달라요. 같은 기간 코스피와 함께 보세요.

## 꼬리표 3종(단타·스윙·중장기): 기간에 맞는 목표·손절과 기간 만료

### 올릴 파일

`app.py`(`2026-10-14 수정17`), `entry.py`(2), `plan.py`(2), `signals.py`(5), `judge.py`(3), `helptext.py`

### 왜 바꿨나

이전에는 꼬리표(중장기/스윙)가 **보호폭과 손절·점검 기준에만** 쓰였고, 매매 계획의 1·2차 목표와 무효가격은 꼬리표와 상관없이 **컨센서스 절반·가까운 저항선·가까운 지지선**으로 정해졌어요. 몇 주 안에 정리할 스윙 매매에 컨센서스(중장기 근거)를 쓰는 건 맞지 않았어요.

### 바뀐 것

- **꼬리표에 `단타` 추가**(보유 종목 편집, 종목 리포트 `보는 관점`, 새 계획, 규칙 화면). 단타는 당일 매매가 아니라 **1~3거래일을 종가 기준으로 가져가는 단기 매매**예요(이 앱은 장중 매매를 지원하지 않아요).
- **꼬리표별 보유 기간(거래일)**: 단타 3, 스윙 10(규칙 화면에서 바꿔요). 중장기는 기간 없이 월간 점검으로 봐요.
- **단타·스윙의 목표·무효가격은 보유 기간 기준**으로 계산해요(컨센서스는 쓰지 않아요).
  - **기간 변동폭 M = 일 변동성(최근 60일) × √보유 기간.** 그 기간에 보통 움직이는 폭이에요.
  - **1차 목표** = 가까운 저항선과 (현재가 × (1 + 0.8M)) 중 작은 값
  - **2차 목표** = 현재가 × (1 + 1.6M)
  - **무효가격** = 가까운 지지선의 2% 아래와 (현재가 × (1 − M)) 중 현재가에 더 가까운 값(최소 1% 아래)
  - **0.8, 1.6, 1.0 같은 계수는 시작 기본값이고 데이터로 검증하지 않았어요.** 진입 평가와 새 계획 화면에 어떤 근거로 나온 값인지 한 줄로 보여줘요.
  - 중장기는 이전과 똑같아요(컨센서스 절반·저항선, 지지선).
- **기간 만료 판단**:
  - 계획에 `진입일`, `보유기간`, `만료일`이 저장돼요(보유 중인 종목이면 **매수일이 진입일**). 예전 계획은 기간 없이 그대로 돌아요.
  - 만료 2거래일 전 `임박`, 만료일 당일부터 **`기간 만료`**(주간 브리핑 "먼저 확인", 매매 계획 화면 경고).
  - 목표 도달과 무효가격 이탈은 만료보다 우선해서 표시돼요.
  - 매매 계획 화면에서 **`기간 연장`**은 **사유를 적어야** 돼요. 사유는 계획 메모에 남고, 만료일은 오늘부터 보유 기간만큼 늘어요.
  - **계획이 없어도** 보유 종목의 매수일 + 보유 기간이 지나면 브리핑에 알려줘요(내 자산 표의 **`기간`** 열에도 `15/10일 (만료)`처럼 표시).
- 새 계획 만들기는 **꼬리표를 먼저 고르면 그 꼬리표 기준으로 기본값이 다시 계산**돼요.

### 알아두세요

- 거래일은 **주말만 제외**하고 공휴일은 반영하지 않아요(공휴일이 있으면 하루쯤 실제보다 빨리 만료로 보일 수 있어요).
- 연장 사유는 계획 메모에 저장돼요. 판단 기록 탭에도 한 줄 남겨 두면 좋아요(자동으로 옮겨 적지는 않아요).
- 단타·스윙은 **비용(왕복 약 0.3%)과 호가 차이의 비중이 커요.** 기간 변동폭이 작은 종목은 기대 수익폭이 비용에 묻힐 수 있어요.
